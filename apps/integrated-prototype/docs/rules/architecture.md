# アーキテクチャ

`src/` のファイルを足す・動かす・直すときに読む。守れる部分は `test/dependency-rules.test.mjs` が検査する。

## 1ファイル1責務

- ファイルの担当を1文で言えること。「経費の請求書の金額検証」は合格、「経費まわりの処理いろいろ」は不合格
- 肥大したら責務の境界で割る。1,000行を超えたファイル（`app.mjs`・`royalty-model.mjs` など）は、触るついでに増やさない
- 画面でも使う計算を、受け口（routes）や DB の処理と同じファイルに置かない（いまの `sales-ops/pipeline-routes.mjs` は借り）

## 業務の領域で分ける

領域は 企画 `planning`・制作 `production`・営業 `sales`・宣伝 `publicity`・売上 `revenue`・経費 `expenses`・精算 `settlement`・会計 `accounting`・台帳 `ledger`、共通基盤 `core`、管理 `admin`。行き先の表は会社ルートの `plans/2026-09-29-integrated-src-restructure.md`。

```
src/<領域>/
├ <領域>-store.mjs   DB の読み書き（その領域の表の持ち主）
├ <領域>.sql         表の定義（D1 の移行ファイルを作る元）
└ <工程>/
   ├ <工程>.jsx          画面
   ├ <工程>-routes.mjs   受け口と手順の組み立て
   └ <工程>-model.mjs    計算と判定
```

- 新しいファイルは `src/` 直下に置かない。当てはまる領域に置く（移し終えるまでは、いまの業務フォルダでよい）
- 迷ったら: 特定の業務の処理 → その領域。どの業務にも属さない土台 → 共通基盤。複数の領域で使いたい処理 → すぐ共通化せず、まず使う領域に置く
- ファイルの移動と中身の改修は、別のブランチにする

## 役と、依存の向き

| ファイル | 役 | してはいけないこと |
|---|---|---|
| `<工程>.jsx` | 画面。HTTP で受け口を呼ぶ | 受け口・DB の役・DB の土台・本番の実行の部品・SQL を持つファイル・表の定義を import する |
| `<工程>-routes.mjs` | 受け口と手順の組み立て。権限の確認、入力の読み取り、store と model を呼ぶ順番、応答 | SQL を直書きする |
| `<工程>-flow.mjs` | 書き込みが多い工程だけ置ける。複数の store への書き込みを1回の batch にまとめる | 受け口・画面・本番の実行の部品を import する |
| `<領域>-store.mjs` | SQL と `org_id` の絞り込みと batch。業務の判断をしない | 受け口・画面・本番の実行の部品を import する |
| `<工程>-model.mjs` | 計算・判定・変換だけの純粋な関数 | DB・受け口・画面・本番の実行の部品を import する。時刻・乱数・環境変数を読む |
| `<領域>.sql` | 表の定義 | main に入った移行ファイルを書き換える（database.md） |

```
画面 ─HTTP→ 受け口 ─→ store ─→ DB
               └──→ model（DB に触れない）
```

- model は引数だけから結果を決める。「今日」が要るなら引数で受け取る（`now = new Date()` のような引数の既定値はよい）。こうするとテストにモックが要らず、1本1秒未満で回る
- テストにモックが要りそうになったら、テストの書き方ではなく model と routes の分け方を疑う
- SQL を書いてよいのは DB の役と、DB の土台（`db.mjs`・`d1-db.mjs`・`cloud-r2-db.mjs`・`local-migrations.mjs`・`sql-in.mjs`・`*-migration.mjs`）だけ。SQL 文は大文字で書く（検査が文そのものを数える）
- 層をこれ以上増やさない。業務の手順は受け口に見える形で書き、抽象の奥に隠さない（書籍の service の層は置かない）

## ほかの領域の表

- ほかの領域の表は SQL で直接読まない。その領域の store の関数を呼ぶ
- まだ領域フォルダへ移していない古い形の表は、直接読んでよい。移したときに store 経由へ直す

## 名前の取り違え

- `production` は「制作」と「本番」の両方に使われている。本番環境のファイルは共通基盤へ寄せ、`production` の名前は制作に使う
- 営業は `sales`、売上は `revenue`。いまの `src/sales/`（売上の明細）は移すときに `revenue/` へ入れる
- DB の役の名前は `-store` にそろえる。いまの `-read`・`-service`・`-data`・`-loader` は移すときに直す

## 検査が見ていること

| 検査 | 見ていること |
|---|---|
| `dependency-rules.test.mjs` | 禁じた import（計算と画面は、SQL 文を持つファイルと本番の実行の部品も）、DB の役と土台の外の SQL 文と DB の呼び出し、model の時刻・乱数・環境変数、`src/` 直下の新しいファイル |

いまの違反は `test/dependency-debt.json` に「返すべき借り」として記録してある。増えたら落ち、直して減ったのに一覧を減らさなくても落ちる。
