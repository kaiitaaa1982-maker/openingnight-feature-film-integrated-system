# OpeningNight フィーチャーフィルム統合基幹システム（公開版・架空データ）

映画の企画・制作・営業・売上報告・経費・精算・会計を、1つのDBと共通のAPIで扱う業務システムの試作です。
映画プロデューサーが、AI（Claude Code・Codex）に実装させて作っています。

## なぜ作るのか

流通・販売の業務にかかる手数料を減らし、作り手にも平等に分配が回る、映画製作の収支管理システムを目指しています。

映画の売上は、配信・パッケージ・放送の会社から届く報告を人が集計し、手数料と経費を引いてから、出資者や権利者へ分けられます。
この事務に人手と手数料がかかり、監督・脚本家・原作者・作曲家などの作り手に届くのは、その残りです。
いくら売れて、なぜその額になったのかも、作り手からは見えにくいままです。

このシステムは、売上の集計・ロイヤリティの計算・製作委員会の分配・報告書づくりを仕組みとAIに任せ、
売上から分配までの根拠を誰でも同じ画面で確かめられるようにします。事務の負担と手数料が減れば、その分を作り手へ返せます。
作り手が、収益の心配をせずに取材や推敲に時間を使える。クリエイターとして仕事を続けていける。そういう場を整えることが目的です。

## できること

| 領域 | 主な機能 |
|---|---|
| 企画 | 作品・権利の取得、受取・支払の MG（最低保証）の台帳 |
| 制作 | 縦書き台本の取込、香盤表（撮影スケジュール）、キャスト・ロケ地 |
| 営業 | 番組販売、放送ウィンドウの一覧と提案書、アベイルズリスト |
| 売上 | 配信・ビデオグラム・放送の売上報告の取込（CSV・Excel）、流通別の集計シート |
| 経費 | 経費集計シート、請求書の取込、出金予定 |
| 精算 | ロイヤリティの計算と報告書、製作委員会の月次収支と分配 |
| 会計 | 仕訳の見え方、PL・BS |
| 共通 | 組織・役割・案件ごとの権限、変更提案と承認、ER図とデータベース定義書 |

金額は浮動小数点を使わず整数円で計算し、分配の端数も1円単位で合うように検算します。

## 架空データで動かす

Node.js 24 以上が要ります。

```sh
cd apps/integrated-prototype
npm ci --ignore-scripts
npm run build
node scripts/seed-all-demo.mjs --db data/demo-sales.sqlite
ON_DB_FILE="$PWD/data/demo-sales.sqlite" npm start
```

ブラウザで `http://127.0.0.1:9041` を開き、`demo-admin@openingnight.invalid` でログインします。
架空の組織 `DEMO-SALES`（作品20本・製作委員会8本・権利者20者・契約80件、24か月分の売上）が入っています。

Windows の PowerShell では、最後の行を次のようにします。

```powershell
$env:ON_DB_FILE = (Resolve-Path data/demo-sales.sqlite).Path; npm start
```

## テスト

```sh
cd apps/integrated-prototype
python3 -m venv .venv && .venv/bin/python -m pip install -r requirements-test.txt
ON_PYTHON="$PWD/.venv/bin/python" npm test
```

テストは外部サービス・認証情報を使いません。分配やロイヤリティのテストは、本体の関数を使わずに元の行から計算し直して照合します。

## この公開版について

- 非公開のリポジトリから、コミット済みのファイルだけを書き出しています
- 中のデータ・人名・会社名・作品名はすべて架空です
- 本番と検証環境（staging）のドメイン・アカウントID・DBのIDは、`example.invalid` やゼロの値に置き換えています。設定ファイルの値のままでは配備できません
- 本番のデータを持ち出す運用スクリプト（バックアップのアップロードと本番移行の準備）は外しています。検証環境向けのスクリプトは残していますが、接続の情報（ホスト名・パスワード）は入っておらず、識別子は架空の値です
- 業務の要件を書いた文書（`docs/requirements/`）は、社内の検討事項を含むため外しています。DB の定義書（`docs/database/`）と開発の規約（`docs/rules/`）は入っています
- 非公開の文書や、非公開のリポジトリ全体のテストの仕組みを前提にしたテストを5本外しています。`agents-map`（`AGENTS.md` が指すパスの実在）、`requirements-trace`（要件の文書との対応）、`req5-master-integration`（非公開の項目定義書との照合）、`test-rules` と `select-tests`（リポジトリ全体のテストの選び方）です。アプリの動きを確かめるテストは外していません
- 移行ファイルのコメントを書き換えたため、PostgreSQL の DDL（`pg/`）はリポジトリの生成スクリプトで作り直し、移行の指紋の期待値も合わせています
- 文書の中の「代表」は作者のこと、`D-0xx` や `[[wiki/...]]` は非公開の決定台帳・ナレッジへの参照です
